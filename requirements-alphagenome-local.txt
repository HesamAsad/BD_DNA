# Isolated venv for the LOCAL, open-weights AlphaGenome model (JAX, real Google
# weights, no API rate limit) -- verified working 2026-09-11 on H100/H200 at our
# model's native 8192nt length. Kept in a separate venv from the project's main
# `nichejepa` env: this is a JAX+TensorFlow stack, unrelated to and heavier than
# the PyTorch stack everything else in this repo uses, and nichejepa's own
# jax-cuda12-pjrt/plugin pins (0.4.33) turn out to be internally mismatched
# against its jax version (0.5.0) -- harmless there since nichejepa never
# exercises real GPU JAX computation, but fatal (a segfault) for this use case.
#
# Setup:
#   python3.10 -m venv /path/to/venv
#   /path/to/venv/bin/pip install -r requirements-alphagenome-local.txt
#   /path/to/venv/bin/pip install /path/to/alphagenome_research/alphagenome
#   /path/to/venv/bin/pip install -e /path/to/alphagenome_research
#
# alphagenome_research itself (google-deepmind/alphagenome_research) is a
# separate, external checkout, not vendored into this repo. As of this
# verification, running it requires ONE source patch on top of that checkout:
# `_upcast_single_batch_predictions` in
# alphagenome_research/src/alphagenome_research/model/dna_model.py calls
# `jax.memory.Space.Host`, an attribute absent from every public JAX build
# tried (0.5.0 and 0.6.2 both lack `jax.memory` entirely -- apparently a
# Google-internal JAX feature not yet upstreamed to PyPI). Patch it to fall
# back to a no-op when the attribute is missing; it's only an optimization
# hint (explicit host-memory placement), not a correctness requirement, since
# callers convert results to numpy immediately afterward regardless:
#
#     host_space = getattr(getattr(jax, "memory", None), "Space", None)
#     if transfer_to_host and host_space is not None:
#       return jax.device_put(x, host_space.Host)
#     return x
#
# Verify with scripts/eval/smoke_local_alphagenome.py before relying on this
# for a headline result.
