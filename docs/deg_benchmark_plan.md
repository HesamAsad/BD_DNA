# DEG zero-shot gene-essentiality benchmark

Protocol-aligned replication of the gene-essentiality experiment in Ma et al.
(2026), *dnaHNet*, so the BD3-LM / SSM checkpoints in this repository can be
put beside the paper's published AUROC numbers. Companion to
`docs/dnahnet_benchmark_plan.md`, which covers the MaveDB and forward-scaling
deliverables.

**Status: harness complete; the full 183,974-gene dataset is built and the
model-free baselines are measured on it. The full GPU scoring run has NOT been
launched** — see
[Cost and the decision you need to make](#cost-and-the-decision-you-need-to-make).

---

## 1. The published protocol

Verbatim from the paper, section *Zero-Shot Gene Essentiality Prediction*:

> "We generated binary essentiality labels for all 62 bacterial organisms in
> the Database of Essential Genes (DEG), with base sequences and annotations
> from NCBI. Genes matching DEG entries by name or sequence identity (>99%)
> were labeled essential. This dataset of 185226 data points evaluates the
> model's capacity to integrate broader genomic context and long-range
> dependencies."

> "For each gene, we extracted an 8192-bp genomic window centered on the gene
> to capture local context. Knockout variants were generated by inserting a
> 15-bp stop codon sequence 12 bp downstream of the start codon (15
> nucleotides were replaced). The log-likelihood difference between wild-type
> and knockout sequences served as the predictor."

Appendix: *"The exact 15bp stop codon sequence used for the gene essentiality
evaluations was the sequence TAATAATAATAGTGA."*

`TAATAATAATAGTGA` is five stop codons back to back (`TAA TAA TAA TAG TGA`), so
a stop is hit in any reading frame. "(15 nucleotides were replaced)" makes this
a **length-preserving substitution**, not an insertion; the window stays 8192 nt.

Published AUROC, for context on the target:

| model | AUROC at increasing training FLOPs |
|---|---|
| dnaHNet (3,2) | 0.5719 / 0.5840 / 0.5993 / 0.6050 @ 8.0e18 / 1.6e19 / 3.2e19 / 6.4e19 |
| dnaHNet (2,2) | 0.5538 / 0.5797 / 0.5854 / 0.5900 @ same budgets |
| StripedHyena2 | 0.5375 / 0.5670 / 0.5720 / 0.5759 @ 1.0e19 / 2.0e19 / 4.0e19 / 7.1e19 |

Our checkpoints sit at ~2.5e18 training FLOPs (6ND, N=100.69M, D=4.19e9 nt) —
**below their smallest budget**. Any comparison must carry that caveat.

Data lands in `data_cache/dnahnet/`:

```
deg_raw/deg_bacteria.csv.zip        DEG experiment table       (pinned sha256)
deg_raw/deg_annotation_p.csv.zip    DEG essential-gene rows    (pinned sha256)
deg_raw/DEG10.nt.gz                 DEG essential-gene DNA     (pinned sha256)
deg_raw/ncbi/<ACCESSION>.gb.gz      one GenBank flat file per replicon
deg_essentiality.jsonl.gz           the benchmark
deg_essentiality.jsonl.gz.metadata.json
```

Records store the wild-type window once plus `cassette_start`; the knockout is
materialised at score time by `deg.knockout_from_record`. That halves the file
and makes it impossible for the two members of a pair to drift apart.

## 3. Assumptions — everywhere the paper is silent

These are also carried in `deg_manifest.json` and copied into every
`.metadata.json`, so a result can never be read without them.

**A1 — the organism list is not exactly reproducible.** DEG's current bacteria
table has **66 essentiality experiments**, spanning **61 distinct organism
names**, **63 distinct nucleotide accessions** and **55 distinct accession
sets**. None of those is 62, and the paper publishes no organism list.

*Our rule:* one benchmark organism per distinct DEG accession set
(version-stripped, sorted), unioning the essential-gene labels of every DEG
experiment that shares that genome. That yields **54 organisms**, of which
**53 build successfully** (see A9).

*A plausible reconstruction of the paper's 62, recorded but not adopted:* the
63 distinct accessions minus `LAUA00000000`, which is a WGS master record with
no retrievable sequence (it fails here too, A9) = **62**. That reading treats
each replicon of a multi-chromosome organism as its own "organism", which is
wrong for a per-organism AUROC breakdown, so we did not adopt it. It is
suggestive enough to mention when comparing counts.

**A2 — sequence-identity matching is ungapped.** The paper's ">99% sequence
identity" was almost certainly a gapped BLAST search. No BLAST binary is
installed on this cluster and none is available through `module`. Matching is
therefore: DEG gene-name aliases (splitting DEG's `tmk/tdk` synonym notation)
against NCBI `/gene`, `/locus_tag`, `/old_locus_tag`, `/gene_synonym`,
**unioned with** exact or equal-length >99%-identity sequence match on either
strand. Measured recall on *B. subtilis* 168 (DEG1001, 271 DEG entries):
221 by name, 260 by sequence, **268 by the union (98.9%)**. The ~1% shortfall
is genuine label noise relative to a BLAST-based build.

**A3 — the knockout offset.** "12 bp downstream of the start codon" is read as
a 0-based offset from the **first base of the start codon**, so the cassette
occupies codons 5–9. The competing reading ("12 bp after the start codon
*ends*") gives 15 and occupies codons 6–10. Both are in frame.
`--knockout-offset 15` switches; a sensitivity check is one flag away and
should be run if a headline number lands near a decision boundary.

**A4 — strand.** Windows are emitted in **gene orientation**: reverse
complemented for minus-strand genes, so the coding sequence reads 5'→3' and
the cassette appears literally as `TAATAATAATAGTGA` at a fixed offset for every
gene. `--orientation reference` keeps the plus strand and writes the reverse
complement of the cassette instead; the two describe the same edit
(`tests/test_deg_benchmark.py::test_both_orientations_describe_the_same_edit`).

**A5 — contig edges.** Replicons annotated `circular` (all complete bacterial
chromosomes here) **wrap around the origin**, preserving both the 8192 nt
length and the centring. Linear contigs **clamp** the window inward, preserving
length but not centring; `window_clamped` records it. Contigs shorter than
8192 nt are excluded and counted.

**A6 — genes longer than the window.** A gene longer than 8192 nt pushes the
knockout site outside the centred window, which would make wild type and
knockout byte-identical and silently inject a zero-difference record. Those
genes are **excluded and counted** (`knockout_site_outside_window`), never
emitted.

**A7 — the gene set.** Only `CDS` features with a single-interval location.
Origin-spanning joins and programmed frameshifts are excluded and counted
(`compound_location`). Genes shorter than `offset + 15 = 27` nt are excluded.

**A8 — aggregation.** The paper reports one AUROC and does not say whether it
is pooled or macro-averaged. **Both are reported. The macro mean of
per-organism AUROC is the headline**, because a pooled AUROC over organisms
with base rates ranging from ~5% to ~28% can be driven by between-organism
differences rather than within-organism discrimination. See §5.

**A9 — one organism cannot be built.** `LAUA00000000` (*Burkholderia
cenocepacia* K56-2, DEG1053) is a WGS master accession; NCBI returns a record
whose sequence content is undefined and Biopython raises
`UndefinedSequenceError`. It is recorded in `failed_organisms` in the metadata
and produces no records. Run with `--strict` to make any such failure fatal.

**A10 — Monte Carlo count for diffusion arms.** The paper's models are
autoregressive with exact likelihood. Our BD3-LM arms estimate a NELBO, so a
Monte Carlo count has to be chosen; it is not a protocol detail we can copy.
Default is `MC_SAMPLES=128`, from the measured MaveDB MC curve
(0.0966 / 0.1242 / 0.1318 / 0.1360 at MC 8 / 32 / 64 / 128). Wild type and
knockout always share the same sampled time and corruption mask (common random
numbers), which is what makes the paired difference low variance.

## 4. Sign convention (and why it is asserted, not assumed)

```
essentiality_score = loss(knockout) - loss(wild type)
                   = log p(wild type) - log p(knockout)
```

**Larger means more essential.** AUROC is sign-sensitive — unlike the
`|Spearman|` used for MaveDB, getting this backwards silently reports
`1 - AUROC` and inverts the conclusion. Three guards:

1. `score_deg.assert_sign_convention()` runs before anything is loaded and
   fails the job if the assembly or `roc_auc` direction is wrong.
2. `summary.json` always carries `macro_auroc_if_sign_flipped`, so an
   inversion is visible at a glance.
3. Verified empirically on the smoke: both AR arms score **well above** 0.5
   (§6), which is only possible with the convention as stated.

## 5. Model-free baselines are mandatory

On MaveDB a zero-parameter feature (count of amino-acid substitutions) scored
0.3649 macro `|rho|`, beating every model *and* the published dnaHNet number.
The benchmark was substantially measuring mutation count. For DEG the knockout
cassette is byte-identical for every gene, so that specific confound is absent
**by construction** — but others are not, and `summary.json` reports all of
these next to the model number, on every run:

| baseline | what it is |
|---|---|
| `gene_length` / `negative_gene_length` | CDS length. Both signs, because AUROC is directional. |
| `window_gc` | GC fraction of the 8192-nt window. |
| `distance_from_contig_start` | `gene_start`. Essential genes cluster near the origin in bacteria. |
| `organism_base_rate` | Each gene gets its organism's essential fraction. Constant within an organism, so its **macro** AUROC is exactly 0.5 by construction, while its **pooled** AUROC can be far above 0.5. This is the pooling confound made measurable, and is why macro is the headline. |
| `random` | Seeded uniform noise. The explicit chance control; must land at 0.5 within sampling error. |

### Measured on the full 183,974-gene benchmark (CPU, 24 s, no model)

`results/dnahnet/deg/baselines-full/summary.json`:

| baseline | macro AUROC | pooled AUROC |
|---|---:|---:|
| `random` (chance control) | **0.4992** | 0.4987 |
| `distance_from_contig_start` | 0.5018 | 0.4524 |
| `window_gc` | 0.5226 | 0.4281 |
| **`gene_length`** | **0.5449** | 0.5340 |
| **`organism_base_rate`** | 0.5000 *(by construction)* | **0.6786** |
| dnaHNet published range, for reference | 0.5375 – 0.6050 | |

Two things follow, and both are load-bearing.

**1. A zero-parameter length feature reaches the published band.**
`gene_length` alone scores macro **0.5449** — above StripedHyena2's smallest
published budget (0.5375) and inside the 0.5538–0.6050 band dnaHNet reports
for its own models. Essential genes are systematically longer, and the
predictor gets that for free. Report `gene_length` beside every model AUROC,
and treat any model score in the 0.54–0.60 range as *not yet distinguishable
from measuring how long the gene is*.

**2. Pooled AUROC is dominated by organism identity.** A predictor that knows
nothing except which organism a gene came from — `organism_base_rate`, constant
within an organism — scores pooled **0.6786**, higher than every number in the
paper's table. Base rates across the 53 organisms range from 0.023
(*S.* Typhimurium 14028S) to 0.720 (*M. genitalium*, a minimal genome), so
pooling hands out most of the discrimination for free. Its macro AUROC is
exactly 0.5, which is the point: **macro is the only version of this metric
that measures within-organism discrimination.** The paper does not say which
it used. If it pooled, its numbers sit *below* a trivial organism-identity
feature, and that has to be said out loud in any comparison.

The random control landing at 0.4992 macro / 0.4987 pooled, with a
per-organism spread of 0.018 (so macro SE ≈ 0.0025 over 53 organisms), also
confirms the metric itself is unbiased at this sample size.

`summary.json` also carries the full `per_organism` breakdown (n, n_essential,
base_rate, auroc) so between- and within-organism effects can be separated.

## 6. What has been verified, and how

**Data preparation, all 53 organisms** (`data_cache/dnahnet/deg_essentiality.jsonl.gz`,
sha256 `4ece3a9c1447fb657d74f48f69622e5bd4861a0694a515ac84d3eaae965c2f4c`,
134 MB, ~20 min on the head node at 1.07 GB peak RSS):

- **183,974 genes, 21,679 essential, base rate 0.1178.** The paper reports
  185,226 data points; we land **0.7% below** it from an independently
  reconstructed organism list, which is the strongest available evidence that
  the reconstruction is substantially the same dataset.
- 53 of 54 organisms built; `LAUA00000000` failed (A9) and is recorded in
  `failed_organisms`. No organism has zero essential genes.
- Label routes: 11,243 matched by both name and sequence, 9,541 by sequence
  only, 895 by name only. Sequence identity carries most of the labelling,
  as A2 predicts.
- Only 656 genes (0.36%) excluded overall: 541 `compound_location`,
  114 `knockout_site_outside_window`, 1 `gene_shorter_than_cassette_site`.
- Knockout difference histogram over all 183,974 records runs 5–15, mode 12,
  never 0 and never above 15.
- **Independent geometry re-verification on 300 records across 10 organisms**
  chosen to be the hard cases: both linear contigs (*M. tuberculosis*
  NC_000962.3 and *B. fragilis* NC_016776.1), the 4-replicon *B. cenocepacia*
  J2315, the 46 kb *Synechococcus* plasmid, the 524-gene *M. genitalium*
  minimal genome, plus ordinary circular chromosomes. Coverage included 127
  minus-strand, 41 origin-wrapping and 10 clamped-linear windows. A script
  that re-reads the cached GenBank files and indexes the genome base by base —
  not using `deg.py`'s builder — confirmed for every one: the window content,
  the centring (modulo the contig for circular, clamped for linear), the start
  codon at `cds_offset`, the whole in-window CDS, `cassette_start ==
  cds_offset + 12`, and that the knockout differs from the wild type only
  inside the 15-nt footprint.

**Data preparation, one organism end to end** (*B. subtilis* 168, NC_000964.3):

- 4,227 genes, 269 essential, base rate 0.0636. Excluded: 7
  `knockout_site_outside_window`, 3 `compound_location`.
- Every window is exactly 8192 nt.
- Every knockout is length-preserving, differs from its wild type **only**
  inside the 15-nt cassette footprint, is never identical to it, and carries
  the literal `TAATAATAATAGTGA` at `cassette_start`. The difference-count
  histogram runs 5–15 (mode 11): fewer than 15 positions change whenever the
  AT-rich window already happens to match some cassette bases. A count of 15
  is *not* an invariant; confinement to the footprint is.
- **Independent re-derivation** (a separate script that re-reads the GenBank
  file and indexes the genome base by base, not using `deg.py`'s builder)
  confirmed on 129 records — 60 random plus-strand, 60 random minus-strand and
  all 9 origin-wrapping — that: the window equals the naive modulo-indexed
  window; the gene midpoint sits at the window midpoint mod contig length; the
  first three bases at `cds_offset` equal the genome's start codon; the whole
  in-window CDS matches the genome; and `cassette_start == cds_offset + 12`.
- Corroborating evidence that `cds_offset` is right: the start-codon
  distribution over all 4,227 records is ATG 3,275 / TTG 551 / GTG 387 /
  other 14 — the expected *B. subtilis* profile.

**A free end-to-end correctness proof from the AR arm.** For a causal
autoregressive likelihood, a substitution at `cassette_start` can only change
the NLL at positions strictly after it. So `essentiality_score` (whole window)
and `essentiality_score_downstream` (positions ≥ `cassette_start`) must be
*bit-identical* — and they are, on all 500 rows, max absolute difference
`0.0`. That simultaneously confirms the knockout offset, the region masks, the
window/tensor alignment and the causal masking are mutually consistent. Two
further sanity readings from the same run: 97.6% of genes have a positive
score (an in-frame stop cassette does raise the NLL, as it should), and the
median `local/total` ratio is 0.854, i.e. ~85% of the whole-window likelihood
shift lives within ±128 nt of the cassette.

**Unit tests:** `43 passed` for `tests/test_deg_benchmark.py`;
`57 passed` together with `tests/test_mavedb_benchmark.py` (no regression).
AUROC is checked against a hand-computed 4-point case, against mid-rank tie
handling, and against `sklearn.metrics.roc_auc_score` on 20 random tie-heavy
draws.

**GPU scoring, all five arms, 500 genes, one organism** (LSF 108248–108252,
H200, 1 GPU, batch 8 pairs, MC 128 for the BD arms) — all five completed:

| arm | objective | AUROC (first-500 subset) | wall clock, 500 genes |
|---|---|---|---|
| uSSM-AR | exact NLL | 0.8202 | 74 s |
| Transformer-AR | exact NLL | 0.7709 | 60 s |
| Transformer-BD | paired NELBO, MC 128 | 0.6617 | 3,467 s |
| BiSSM-BD | paired NELBO, MC 128 | 0.6509 | 4,481 s |
| uSSM-BD | paired NELBO, MC 128 | 0.6019 | 3,372 s |

Every arm lands **well above 0.5**, which is only possible with the sign
convention as stated in §4 — a flipped sign would have put all five in the
0.18–0.40 band. Both objectives (exact AR NLL and the paired diffusion NELBO
with common random numbers) are therefore wired up correctly.

**Do not quote those AUROCs as benchmark results.** They come from
`--max-genes 500`, which truncates in genome order, and the first 500 genes of
a bacterial chromosome are the origin-proximal replication/ribosome block:
base rate 0.144 versus the organism's 0.064, `distance_from_contig_start`
baseline 0.227 and `window_gc` 0.248 (both wildly informative purely from the
truncation). They establish that the pipeline runs, that the sign convention
is correct, and how fast each arm is — nothing else. `--sample-genes` was added
for exactly this reason and is what any interpretable subset run must use; on
a seeded 500-gene sample the base rate recovers to 0.064 and the baselines
return to 0.44 / 0.60 / 0.53.

`MODEL_LENGTH` is 8192 and every checkpoint's block size (1 for AR, 256 for

## 8. Cost, and the decision you need to make

Measured on H200, 1 GPU, model length 8192, from LSF 108248–108258:

| arm | forwards per gene | measured | **full 183,974-gene set** |
|---|---|---|---|
| Transformer-AR | 2 (exact NLL) | 500 genes in 60 s | **~4 GPU-h** |
| uSSM-AR | 2 (exact NLL) | 500 genes in 74 s | **~4 GPU-h** |
| uSSM-BD, MC 128 | 256 | 6.74 s/gene | **~345 GPU-h** |
| Transformer-BD, MC 128 | 256 | 6.93 s/gene | **~354 GPU-h** |
| BiSSM-BD, MC 128 | 256 | 8.96 s/gene | **~458 GPU-h** |

(The AR figures include ~40 s of fixed model-load time in a 60–74 s run, so
they are upper bounds; the true marginal cost is under 2 GPU-h per arm.)

**Batch size is not a lever.** Measured at 8 / 16 / 32 pairs: 16 buys ~4% over
8 and 32 buys nothing (the GPU is already saturated by 8192-nt sequences). Worse,
`BATCH_SIZE=32` **breaks the Transformer-BD compile** — flex attention on the
16,384-token concatenated `(xt ‖ x0)` input raises
`InductorError: NoValidChoicesError` (LSF 108259). Keep `BATCH_SIZE` at 8–16.

So: the two AR arms cost **under 8 GPU-hours together** — just run them. The
three BD arms at MC 128 cost **~1,160 GPU-hours for one seed**, which is not a
reasonable ask. Options, in the order I would consider them:

1. **Stratified subset at full MC.** 20,000 genes (`--sample-genes 20000`,
   which draws uniformly across the whole file and so keeps all 53 organisms
   in proportion) costs 37 / 38 / 50 GPU-h for uSSM-BD / Transformer-BD /
   BiSSM-BD, **~126 GPU-h for all three**.
   At n=20,000 with an 11.8% base rate the macro-AUROC standard error is
   ~0.008, well below the 0.03–0.05 gaps the paper reports between models.
   **This is my recommendation.**
2. **Lower MC on the full set.** MC 32 costs ~86 / 89 / 115 GPU-h per arm
   (~290 GPU-h total). Whether MC 32 suffices at 8192 nt is *not* answered by the MaveDB curve,
   which was measured at 256 nt with 32× fewer positions per sample. It needs
   its own measurement: a 500-gene MC sweep at 8 / 32 / 128 costs ~3 GPU-h
   total and should precede any full BD run either way.
3. **Full set, full MC.** ~1,160 GPU-h for one seed, ~2,320 for the two seeds
   the MaveDB experience says are needed to separate arms. Only worth it for a
   final publication number, and only after (1) shows the arms differ at all.

For AR the likelihood is exact, so a second seed changes only the baseline RNG
— one run per AR arm suffices. The BD arms do need two seeds, and the MaveDB
lesson applies: compare ensembles to ensembles, never a per-seed macro against
an ensembled one.

Before committing to any of this, re-read §5: `gene_length` already scores
0.5449 macro. It costs nothing, it is in every `summary.json`, and it should
probably decide whether the expensive BD runs are worth doing at all.

## 9. Interpretation contract

- **Headline metric is the macro mean of per-organism AUROC.** Pooled AUROC is
  reported alongside; if the two disagree, the pooled number is being driven
  by between-organism base-rate differences and the macro number is the honest
  one. `organism_base_rate` in the baselines quantifies exactly how much room
  there is for that confound.
- **Always report `gene_length` beside the model.** See §5.
- **Objectives are not the same.** dnaHNet uses exact autoregressive
  likelihood. Our AR arms match that; our BD arms report a Monte Carlo
  diffusion NELBO with common random numbers. Keep the labels visible, and
  never average an AR and a BD number.
- **Compute is not matched.** Our checkpoints are at ~2.5e18 training FLOPs,
  below dnaHNet's smallest published budget (8.0e18). A lower AUROC is the
  expected outcome and is not evidence about architecture.
- **Compare ensembles to ensembles.** As on MaveDB, a per-seed macro is lower
  than a two-seed ensemble; mixing the two invents a phantom regression.
- **The dataset is ours, not theirs.** 53 organisms rather than 62, ungapped
